# Paper + Figma: экспорт кадров и склейка

Используй **только MCP продуктов** Paper и Figma (серверы из конфигурации Cursor: например `user-paper` / `plugin-paper-desktop-paper` и `plugin-figma-figma`). Перед вызовами Paper впервые в сессии прочитай гайд: `get_guide` с `topic: "paper-mcp-instructions"`.

## Вход

- **Источник**: URL или идентификатор файла.
  - **Figma**: полный URL вида `https://www.figma.com/design/:fileKey/...?node-id=...` (или ветка: `.../branch/:branchKey/...` — тогда **fileKey = branchKey**). При необходимости страница/фрейм задаётся через `node-id` в URL или отдельным фреймом верхнего уровня на странице.
  - **Paper**: MCP работает с **открытым в Paper Desktop** документом. URL в чате — ориентир: **список страниц одного файла через MCP не запрашивается**; переключение страницы делается открытием **конкретного URL страницы** в приложении Paper (см. раздел «Несколько страниц»). Если `get_basic_info` отвечает «Open a Paper file» — сначала откройте файл в Paper Desktop вручную, затем снова переключайте страницы.
- **Префикс инструмента** `{tool}` — определяется источником: `paper` для Paper MCP, `figma` для Figma MCP. Всегда стоит **первым** сегментом имени файла.
- **Префикс имени файла** — берётся из **названия страницы** (`pageName` из `get_basic_info`): slug агента и модели через `__`. Например страница «OpenCode + GLM 5.1» → `opencode__glm-5.1`. **Не добавляй slug страницы повторно** — имя страницы уже содержит агент и модель.
- **Типы экранов** для трёх отдельных файлов и склейки: `desktop`, `mobile`, `promo` (часть имени перед `@2x`).
- **Масштаб экспорта**: по умолчанию **2x** (ретина). Имена файлов всегда с суффиксом **`@2x`** перед расширением.

## Выход

Каталог проекта: **`tmp/download/`** (создай при отсутствии). Не показывай пользователю сырые node id из MCP в ответе.

## Именование файлов

Шаблон имени файла начинается с **префикса инструмента** `{tool}__`:

**Одна страница** в файле (короткий шаблон) — суффикс **`@2x`** обязателен:

```text
{tool}__{agent}__{model}__{screen}@2x.png
```

**Несколько страниц** в одном файле — в имя добавляй **`{page-slug}`** (между `model` и `screen`), чтобы кадры разных страниц не перетирали друг друга:

```text
{tool}__{agent}__{model}__{page-slug}__{screen}@2x.png
```

`{page-slug}`: нормализованный **`pageId`** из `get_basic_info` (например `p-0`) или краткое имя страницы из букв/цифр/дефисов (например `kilo-opus-4-7`). Один и тот же slug для всех четырёх файлов одной страницы.

Где `{tool}` ∈ `paper` | `figma`, `{screen}` ∈ `desktop` | `mobile` | `promo`.

Склейка всех трёх (порядок слева направо: **desktop, mobile, promo**):

```text
{tool}__{agent}__{model}__all@2x.png
```

или для конкретной страницы при мульти-страничном экспорте:

```text
{tool}__{agent}__{model}__{page-slug}__all@2x.png
```

Нормализация сегментов (чтобы имена были безопасны для файловой системы):

- приведи `agent` и `model` к ASCII, нижний регистр;
- символы `/`, `\`, `:`, пробелы → `-` или удаление;
- не добавляй версию файла в имя (если нужен повторный экспорт — можно добавить суффикс `-2` только по явной просьбе).

Пример (Paper):

```text
paper__codex__gpt-5.5-xhigh__desktop@2x.png
paper__codex__gpt-5.5-xhigh__mobile@2x.png
paper__codex__gpt-5.5-xhigh__promo@2x.png
paper__codex__gpt-5.5-xhigh__all@2x.png
```

Пример (Figma):

```text
figma__cursor__glm-5.1__desktop@2x.png
figma__cursor__glm-5.1__mobile@2x.png
figma__cursor__glm-5.1__promo@2x.png
figma__cursor__glm-5.1__all@2x.png
```

Пример **нескольких страниц** одного файла:

```text
paper__codex__gpt-5.5-xhigh__p-0__desktop@2x.png
paper__codex__gpt-5.5-xhigh__p-1__desktop@2x.png
```

## Paper: несколько страниц одного файла

MCP **не отдаёт список страниц** документа: активна только **текущая страница** в Paper Desktop.

**Программное переключение страниц НЕ работает**: `open -a Paper "<URL>"` открывает Paper, но **разрывает соединение MCP** с файлом (возвращает «Open a Paper file»). Повторный вызов с корневым URL файла тоже не восстанавливает подключение. Инструментов переключения страниц в самом MCP нет.

**Единственный рабочий способ** — пользователь переключает страницу вручную в Paper Desktop, после чего агент вызывает `get_basic_info` для подтверждения текущей страницы.

Рабочий цикл для каждой страницы:

1. Попроси пользователя переключить страницу в Paper Desktop.
2. Дождись подтверждения (пользователь пишет «готово», «да» или подобное).
3. Вызови **`get_basic_info`** и проверь `pageName` / `pageId` — должны соответствовать ожидаемой странице.
4. Экспорт артбордов этой страницы (`export` **2x**, перемещение в `tmp/download/`), затем склейка (см. раздел «Склейка»).
5. Повтори шаги 1–4 для каждой следующей страницы.

Не пытайся вызвать `open -a Paper` для переключения — это только ломает MCP-соединение.

## Сопоставление слоёв с desktop / mobile / promo

1. **По имени** (предпочтительно): фрейм/артборд содержит подстроку без учёта регистра: `desktop`, `mobile`, `promo` (или осмысленные русские названия, если они однозначны — **`mobile` только один**).
2. **По размеру** (если имя неоднозначно, из контекста воркшопа):
   - ширина **375** → `mobile`;
   - ширина **1400** → если два кадра 1400px, тот что по смыслу лендинг/промо → `promo`, основной интерфейс приложения → `desktop` (при сомнении отдай приоритет подписи слоя в дереве).

Для Figma: `get_metadata` по `fileKey` и корневому `nodeId` страницы (часто страница из URL или `0:1` — брать из контекста URL) → найти id трёх фреймов → для каждого `get_screenshot`.

Для Paper: `get_basic_info` — список артбордов с размерами → при необходимости `get_tree_summary` с корня документа / страницы → зафиксировать три `nodeId`.

## Скачивание изображений

### Figma (`get_screenshot`)

- Параметры: **`fileKey`**, **`nodeId`** (формат `123:456`; из URL `node-id=1-2` → `1:2`).
- **Масштаб 2x**: если API позволяет задать масштаб рендера экспорта — используй **удвоенное разрешение** (аналог `@2x`). У официального MCP уточни в описании инструмента; при отсутствии явного параметра скачай максимально доступный PNG и не заявляй ложно про 2x.
- По умолчанию инструмент возвращает **краткоживущий URL** и инструкции `curl` — **предпочитай скачать через `curl`** в `tmp/download/` с целевым именем `{tool}__{agent}__{model}__{screen}@2x.png` или с **`__{page-slug}__`** при мульти-страничном экспорте.
- Включай **`enableBase64Response: true`** только если недоступен исходящий HTTP / shell; тогда декодируй base64 и запиши файл сам.

### Paper

- **Способ 1 — `export` + `mv`**: для каждого артборда вызови `export` с `nodes: { "<nodeId>": [{ "format": "png", "scale": "2x" }] }`. Инструмент **не принимает путь вывода** — файл всегда сохраняется в `~/Downloads/` с именем слоя. Сразу после экспорта перемести: `mv ~/Downloads/"<имя из ответа>" tmp/download/<целевое-имя>`.
- **Способ 2 — `get_screenshot` + base64**: вызови `get_screenshot` с **`scale: 2`**, **`transparent: true`**. Ответ — base64 PNG. Декодируй и запиши напрямую в `tmp/download/` под целевым именем. Этот способ не зависит от `~/Downloads` и не требует отдельного `mv`.
- **Рекомендация**: если в окружении доступна запись в `tmp/download/` и shell-декодирование base64 — предпочитай **Способ 2** (меньше шагов, нет зависимости от `~/Downloads`). Если base64-ответ обрезан по размеру — переходи на **Способ 1**.

Для превью без записи на диск можно ограничиться `get_screenshot` без сохранения; для финального артефакта воркшопа — один из двух способов выше.

## Порядок пайплайна (полный цикл)

Для одной страницы / одного набора из трёх экранов выполняй **строго в этом порядке**:

1. **Экспорт 2x** — три файла `desktop`, `mobile`, `promo` в `tmp/download/`.
2. **Оптимизация экранов** — все три PNG (см. «Оптимизация PNG»).
3. **Склейка** — `__all@2x.png` (ImageMagick или `stitch_exports.py`; скрипт оптимизирует результат сам).
4. **Копии `-2400`** — для каждого из четырёх файлов (3 экрана + all).
5. **Оптимизация `-2400`** — все четыре уменьшенные копии.
6. **Дата прогона** — запиши `runDate` в `site/data/runs.json` (см. раздел «Дата прогона»).

Итого **8 файлов** на страницу плюс поле даты в results. Не пропускай шаг 2 и 5 — сырые экспорты из Paper/Figma часто весят в несколько мегабайт каждый. Не пропускай шаг 6.

## Склейка «все»

Требование: **прозрачный фон**, выравнивание **по верхнему краю**, горизонтальный **отступ 100 px** между тремя изображениями; порядок: **desktop · mobile · promo**.

Используй **ImageMagick** (`magick`). Запуск из каталога проекта:

```bash
magick \
  -background none \
  tmp/download/{tool}__{agent}__{model}__desktop@2x.png \
  tmp/download/{tool}__{agent}__{model}__mobile@2x.png \
  tmp/download/{tool}__{agent}__{model}__promo@2x.png \
  -gravity North \
  +smush 100 \
  tmp/download/{tool}__{agent}__{model}__all@2x.png
```

`+smush 100` склеивает по горизонтали с зазором 100px между **каждой** парой соседних изображений. `-gravity North` выравнивает по **верхнему краю** на холсте высотой максимального изображения. Фон остаётся прозрачным благодаря `-background none`.

Для страницы с `{page-slug}` подставь тот же slug во всех путях (включая выходной `__all@2x.png`).

После склейки проверь визуально при возможности (размеры, порядок).

Альтернатива без ImageMagick — скрипт `scripts/stitch_exports.py` (Pillow): та же склейка (порядок desktop · mobile · promo, верхнее выравнивание, прозрачный фон, gap) и **автоматическая оптимизация результата** (см. «Оптимизация PNG»; отключается `--no-optimize`):

```bash
python3 .agents/skills/paper-figma-export-stitch/scripts/stitch_exports.py \
  --out tmp/download/{tool}__{agent}__{model}__all@2x.png \
  tmp/download/{tool}__{agent}__{model}__desktop@2x.png \
  tmp/download/{tool}__{agent}__{model}__mobile@2x.png \
  tmp/download/{tool}__{agent}__{model}__promo@2x.png
```

## Оптимизация PNG

Все экспорты (3 экрана, склейка и копии `-2400`) прогоняй через **lossy**-сжатие: `pngquant` с perceptual quality **до 90** (`--quality 0-90`). Плоские макеты с палитрой на токенах сжимаются в 3–6 раз без заметной потери (типичная суммарная экономия ~80%).

### Скрипты (предпочтительно)

Общая логика в `scripts/optimize_png.py` (pngquant lossy `0-90`; при отсутствии pngquant — Pillow 256 цветов).

**Пакетная оптимизация** всех PNG в `tmp/download/` (шаги 2 и 5 пайплайна):

```bash
python3 .agents/skills/paper-figma-export-stitch/scripts/optimize_exports.py
# или явный список / каталог:
python3 .agents/skills/paper-figma-export-stitch/scripts/optimize_exports.py tmp/download/paper__*__*.png
```

Флаги: `--quality 0-90` (по умолчанию, lossy до 90), `--dry-run` — только список файлов.

**Склейка** через `stitch_exports.py` оптимизирует выходной `__all@2x.png` автоматически (`--no-optimize` — отключить).

### Ручной pngquant

```bash
pngquant --quality 0-90 --speed 1 --force --ext .png tmp/download/<файлы>.png
```

- `--quality 0-90`: lossy-квантование, верхняя граница perceptual quality = **90**; нижняя 0 — pngquant подбирает максимальное сжатие в этом диапазоне.
- Прозрачность сохраняется.
- Палитра 256 цветов: для плоских заливок её хватает с запасом. Если в макете фотореалистичные изображения или плавные градиенты — сузь диапазон (`--quality 70-90`) либо используй `oxipng` без квантования (lossless).
- Проверка деградации: перед массовым прогоном просмотри самый тяжёлый файл — бандинг плоских заливок, чёткость мелкого текста.
- `pngquant` не установлен (`brew install pngquant`) — скрипты откатываются на Pillow-квантование; при чисто ручном пути через magick оптимизацию запускай отдельно, не забывая про `-2400` копии.

## Уменьшенные копии 2400px

Для **каждого** файла (3 экрана + склейка) создай уменьшенную копию, у которой **большая сторона = 2400px**, пропорции сохранены. Имя копии: между `{screen}` и `@2x` добавляется суффикс **`-2400`**.

Шаблон:

```text
{tool}__{agent}__{model}__{screen}-2400@2x.png
{tool}__{agent}__{model}__all-2400@2x.png
```

Для мульти-страничного экспорта:

```text
{tool}__{agent}__{model}__{page-slug}__{screen}-2400@2x.png
```

### Алгоритм

1. После создания полного 2x файла определи его размеры (`magick identify`).
2. Определи большую сторону (max(width, height)).
3. Рассчитай масштаб: `scale = 2400 / max_side`.
4. Если `max_side > 2400` — уменьши; если `max_side < 2400` — увеличь. Если `max_side == 2400` — просто скопируй.
5. Используй ImageMagick:

```bash
# Для ландшафтных (ширина > высота):
magick input.png -resize 2400x2400 -background none output-2400@2x.png

# Для портретных (высота > ширина):
magick input.png -resize x2400 -background none output-2400@2x.png
```

Общий подход — всегда указывать ограничивающий прямоугольник `2400x2400` с сохранением пропорций:

```bash
magick input.png -resize 2400x2400 -background none output-2400@2x.png
```

ImageMagick автоматически выберет корректную ось для масштабирования при сохранении пропорций.

6. Проверь размеры копий (`magick identify`): большая сторона должна быть ровно 2400px (±1px из-за округления).
7. **Оптимизируй** каждую `-2400` копию (шаг 5 пайплайна): `optimize_exports.py` или `pngquant`.

## Дата прогона (`runDate`)

После экспорта **обязательно** запиши день эксперимента в `site/data/runs.json`. Это не дата склейки и не дата коммита сайта.

Поле: **`runDate`**, строка **`YYYY-MM-DD`**, календарный день в **Europe/Moscow**. Стоит сразу после `model`. Тип в `site/src/lib/types.ts`: необязательное `runDate?: string`.

Сопоставь прогон с записью по `{tool}` + агент + модель (или по basename картинок `paper__…` / `figma__…`). Если записи ещё нет и в этой же задаче добавляешь ран — `runDate` обязателен в новом объекте.

### Откуда брать дату

**Paper (предпочтительно `createdAt` файла):**

1. Вызови `list_files` (лимит до 200).
2. Найди файл по **id** текущего документа (`get_basic_info` / `open_file`) или по имени, совпадающему со страницей («Cursor + GLM 5.3 Flash»).
3. Возьми **`createdAt`** (unix ms). **Не используй `updatedAt`**: у пачки файлов он часто один и тот же после массового касания.
4. Переведи в московский день:

```bash
python3 - <<'PY'
from datetime import datetime, timezone, timedelta
ms = int("CREATED_AT_MS")
print(datetime.fromtimestamp(ms/1000, tz=timezone(timedelta(hours=3))).strftime("%Y-%m-%d"))
PY
```

Если макет — страница в сборнике (например «Epic Design Battle»), а в команде есть **отдельный файл** с тем же агентом и моделью — дата с **отдельного** файла (`createdAt`), не со сборника.

**Figma:** MCP обычно не отдаёт `createdAt`. Для **нового** рана пиши сегодняшний день в Europe/Moscow. Для уже существующей записи с заполненным `runDate` не затирай его экспортом картинок.

### Как писать

- Пустой или отсутствующий `runDate` — запиши найденную дату.
- Уже стоит дата и это повторный экспорт тех же экранов — **не перезаписывай**.
- Перезаписывай только по явной просьбе или если старое значение заведомо про дату архива/коммита, а не прогона, и новая дата из Paper `createdAt` надёжнее.

В ответе пользователю укажи, какой `runDate` записан и откуда (Paper `createdAt` / сегодня для Figma).

## Завершение

- Кратко перечисли созданные файлы в `tmp/download/` (без внутренних id): 3 экрана + `all` + четыре `-2400` = **8 файлов**.
- Укажи суммарный размер до/после оптимизации, если прогонял `optimize_exports.py` (строка `total:` в выводе).
- Укажи `runDate` и источник (Paper `createdAt` или календарный день для Figma).
- Если какой-то из трёх кадров не найден в файле — остановись, опиши что есть в дереве слоёв и что не удалось сопоставить; не выдумывай node id.
